## حماية البيانات: لا نفترض وجود نسخة شاملة

راجعنا public/mindful-runtime.js وQatraAwarenessPlugin.kt:

1. الخيار المطلوب للوعي هو الإعدادات، ثم «بيانات دقيقة وعي والدفتر»، ثم «تصدير البيانات». اختر موقعًا محليًا خاصًا عند ظهور منتقي الملفات.
2. مسار التصدير الكامل لهذه الوحدة يصدر صيغة qatra-awareness ذات schemaVersion 1، وهي الصيغة التي يقبلها الاسترجاع في الإعدادات.
3. تصدير الدفتر وحده باستخدام scope=notebook يصدر مصفوفة JSON مختلفة؛ لا نعتمده بديلًا عن تصدير وحدة الوعي القابل للاسترجاع.
4. هذا ليس تصديرًا شاملًا للتطبيق: لا نعتمد عليه لحفظ إعجابات العبارات أو تقدم الحديقة. ولم يثبت أنه يحفظ المجموعات الشخصية والمواعيد وتفضيلات التطبيق أو صلاحيات Android.
5. يجب مراجعة العناصر غير المشمولة وتسجيلها محليًا أو إيجاد وسيلة مناسبة لحفظها قبل أي إزالة. وجود ملف JSON وحده لا يثبت استرجاع البيانات كاملة.
6. ملف التصدير غير مشفر. لا ترفعه إلى GitHub أو المحادثة، ولا ترسل محتوى الدفتر أو مفاتيح التوقيع. لا يوجد تصدير أو رفع تلقائي في هذه الحزمة.

لا تستطيع تغييرات المصدر الجديدة إضافة نسخة احتياطية إلى التطبيق القديم المثبت دون تثبيت كود جديد عليه. لذلك لا نعلن تأمين البيانات غير المشمولة بمجرد كتابة هذه الخطة.

## تثبيت التوقيع في البناء

- build-identity.py يقارن شهادة المفتاح المستعاد بالبصمة المقصودة قبل البناء.
- يصدّر مساره المطلق في QATRA_KEYSTORE_FILE إلى الخطوات اللاحقة.
- Gradle يطلب وجود هذا المسار ويربط debug وrelease صراحةً بمخزن qatraPersistent؛ لا يعتمد على مخزن Debug الضمني.
- لا ينشئ أي مسار مفتاحًا بديلًا عند غياب المفتاح المطلوب.
- versionCode يشتق من رقم تشغيل هذا الـworkflow ورقم المحاولة. يجب استخدام تشغيل أحدث للتحديث التالي؛ لا يعاد تشغيل عملية أقدم بعد تثبيت إصدار أحدث.
- قبل تسليم APK يتحقق السكربت من الشهادة ومعرّف الحزمة ورقم الإصدار الفعلي، ويخرج تقرير qatra-build-identity.
- هذا خط APK مباشر بالمفتاح الحالي، وليس إعلان جاهزية توزيع متجر أو تغييرًا إلى مفتاح نشر جديد.

## بوابات الانتقال البشري

الحالة الحالية: data_backup_confirmed=false، uninstall_authorized=false، update_installation_proven=false.

1. تأمين البيانات الممكنة ومراجعة غير المشمول؛ لا يفترض نجاحه تلقائيًا.
2. بناء النسخة الجديدة وفحص تقرير هويتها دون حذف القديمة.
3. مراجعة ما سيُستعاد وما قد لا يُستعاد مع المستخدم.
4. طلب إذن منفصل وصريح قبل إزالة النسخة القديمة. لا تنفذ هذه الحزمة هذه الخطوة.
5. بعد الانتقال الموافق عليه، استرجاع ملف الوعي بتأكيد المستخدم وتجديد الصلاحيات عند الحاجة؛ لا إعادة جدولة للمواعيد تلقائيًا في هذه الحزمة.
6. إصدار بناء لاحق من خط الشهادة نفسه وتجربة تثبيته فوق النسخة الجديدة مع بقاء البيانات. لا نصف المشكلة بأنها مثبتة الحل قبل ذلك.

يجب الاحتفاظ بالمفتاح الثابت في نسخة احتياطية آمنة خارج المستودع، دون إرساله في المحادثة. لا تحذف أيًا من الملفات القديمة أثناء التجهيز.
